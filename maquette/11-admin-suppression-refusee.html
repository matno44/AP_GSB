Comment lire cet écran.
  • Le refus n'est pas un message d'erreur, c'est une explication suivie d'une issue. Un écran qui dirait seulement « suppression impossible » pousserait l'administrateur à chercher un contournement — typiquement supprimer les fiches d'abord, ce qui déclencherait justement la cascade destructrice décrite ici.
  • Le refus est structurel, pas cosmétique. fk_fichefrais_visiteur est en RESTRICT : même si quelqu'un forçait la requête, la base refuserait. L'écran explique une règle que le moteur applique déjà.
  • Les justificatifs sont mentionnés à part parce qu'ils ne sont pas dans la base : les fichiers ne sont effacés que par le code PHP. Une suppression en cascade côté base les laisserait sur le disque sans que rien ne les référence.
  • Pour un compte réellement sans donnée liée (cas Morel Inès), cet écran n'apparaît pas : on passe directement à une confirmation de suppression, qui énonce que l'opération est irréversible.
